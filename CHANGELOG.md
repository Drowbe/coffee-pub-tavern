## [0.4.0] - 2026-09-25

### Fixed
- **Security: a page on another site could make changes as whoever was signed in.** A signed-in person's cookie still went along with a request from another origin on the same site (every environment is a subdomain of the host's domain), and a plain form needs no permission to send one. Now any POST, PUT, PATCH or DELETE that carries a cookie and comes from another origin is refused with 403 "This request came from another site, so it was refused." Not affected: Studio and anything else signing with a `Bearer` token, requests with no cookie, and `POST /login`, the landing page's sign-in. Follow-ups are GitHub #70. Documented in `architecture-overview.md`. Checked by the tool: `npm run check` passes, including the new `check-template-switch` and `check-origin`, and `check-modules`, `check-templates` and `check-themes`; any live check is QA's to report.
- Theme import follow-ups (GitHub #67): an environment holds at most 100 themes, and an import past that is refused with "This environment has 100 themes, the most it can hold. Delete one to import another."; control and text-direction characters are taken out of a theme's name and author, and a name is cut at 40 whole characters (never half an emoji); a file in an encoding the server can't read gets "That isn't a Magpie theme file."; a UTF-16 file imports; and Manage's Theme tab fits a phone. `userguide-themes.md` covers it. Checked by the tool: `npm run check` passes, including the new `check-template-switch` and `check-origin`, and `check-modules`, `check-templates` and `check-themes`; any live check is QA's to report.
- **Security: the stream access key could be used to sign in as anyone, an owner included.** `GET /api/status`, which the access key in every OBS link can read, sent every person's personal sign-in link, and a personal link signs its holder straight in. Separately, anyone signed in, a guest or a key holder could read every space's guest link (`GET /api/spaces`, `GET /api/presence`, the aside answers). Now a personal link is sent only to owners and to that person, and never in `/api/status`; a guest link only to owners and to members of that space who may manage its guest link (anyone else gets `null`). The environment's AI key and the host's managed AI keys are now encrypted at rest (a plain one is encrypted when first loaded), and `app.json`, `host.json`, `ai.json` and `secrets.key` are readable only by the server's own user, set on every start and after a restore or a migration. Moving a single server onto a hosted one keeps its AI key and two-step sign-in working, re-encrypted to the host's key. An AI key that can't be read on this server (data restored onto another host) no longer stops the other AI settings from saving; the AI settings say to enter the key again. **After upgrading, regenerate the stream access key (Manage > Environment > Access key) and give Coffee Pub Studio, or each OBS source, the new one.** File modes for the chat and module files, and some checks, are follow-ups (GitHub #69, in `known-issues.md`). Verified live on throwaway servers in every role, with the pages in a headless browser; the original exploit no longer works.
- Password boxes are masked (GitHub #61): Manage's new user, a profile's new password, and on the host console a host admin's and a first owner's. Each has a **Show** / **Hide** button, and is masked again after saving or cancelling. A check now fails on a password or secret field that isn't masked. Verified live.
- The Calendar no longer shows an error after the whole app is popped out, or when several modules close at once (GitHub #21). The chat in a window of its own now puts the cursor in its message box and sends on Enter; both used to show an error (GitHub #22). Polls and the To-do no longer show an error after they are closed, and the drop menu no longer fails when a drop offers two or more choices. Verified live.
- A link to a Calendar event opens the event again when the link is what first loads the Calendar (Calendar 1.17.11, GitHub #19), including the Calendar's space page and a Calendar just opened on a space's canvas. Before, it opened the Calendar but not the event.
- The page for a personal link that was turned off or replaced (`GET /j/:token`) shows the environment's name and icon (GitHub #18). Before, the page's own security policy blocked its script, so it always said "Coffee Pub". `tools/check-syntax.mjs` now fails on any page whose inline script its own security policy would block.
- Six things found and fixed while the pages were renamed (step 5b of the Names plan): inviting someone to a private conversation from **Who's around** always failed; Manage > Users never showed that someone was "in <space>"; a module's configuration never showed its line about each space's moderators choosing their own settings; the **Spaces** link during a call reloaded the page and dropped the call; the **Clear chat** overlay lost its styling to a broken style-sheet comment; and an old link to an item (`/modules/<id>?space=...#ref=...`) opens its item again. Verified live without a call; anything in a call is read as code only.
- On the Modules tab, a change the server refuses now changes nothing (GitHub #17). Before, a request that turned a module off together with the modules that need it, and also asked for something refused (an unknown run mode, say), still left them off while showing the error. Verified live, through the API and on the Modules tab.
- A Planner journey can be up to 7 days long (Travel 0.7.31, GitHub #14 and #15). Before, anything over 24 hours was cut to 24 hours, so a 24 h 30 min flight saved as 24 h and its arrival showed the same time as its departure. A day's time column now puts a later-day arrival on its own line ("→ 10:00 AM", then "the next day" or "+2 days"), and the cards and the editor say it in full. **Trip ends** sits on the day the last journey arrives, and after the plan's last day it shows the date over the time. A length over 7 days is refused with "A length can be at most 7 days (168 hours)." (a journey's length, a return leg's, and how long it takes from the stop before). The Bookings, Money and Decisions views follow the environment's clock ("9:40 AM" on the 12-hour clock). Verified live.
- A refused save now changes nothing (GitHub #16). Before, the parts of a save that were fine were kept even though the page showed an error: Manage's settings (a clock change sent with a currency the server doesn't know), editing a person (a refused role still saved the new login or name), a space (a refused link or profile still saved the name or description) and, on the host console, an environment (a refused status still saved the name or plan). Now the whole save is refused, and the error names the field to fix. A module update that is refused part-way can still apply its first part; that is GitHub #17, in `known-issues.md`. Verified live.
- Manage's **Currency** list shows every currency by its code and name, the common ones first, and the server refuses a code it doesn't know with "XYZ is not a currency this server knows. Choose one from the list, such as USD." (GitHub #4, the server's setting). Before, a request made directly could store any three letters. A code already stored is kept, and still shown in the list. The currencies are the ISO 4217 codes the server's own Node knows (`Intl.supportedValuesOf('currency')`, `CURRENCIES` in `server/store.js`). The Planner's trip currency is still typed; a shared picker is next. Verified live.
- The Planner (Travel 0.7.27) is clearer about journeys and stays (GitHub #5, #7, #8, #10, #11). A length is entered as hours and minutes and shown as "8 h 15 min", instead of a number of minutes. A journey's fields say what they are ("Departure day", "Departure time", "Flight time", "Departs from", "Arrives at", "Departure airport", "Departure gate", "Coach" for a train), and once it has a time and a length the form shows when it arrives, "the next day" when it runs past midnight (time zones are not taken into account); a flight's and a train's card say "Departs" and "Arrives". A stay has **Check in** and **Check-in time**, and **Check out** is now any date after check-in, even after the trip's last day, with its time; the stay's **Room** field is called Room again. The Bookings view shows a stay as a date range with its nights. The trip form asks for **Name**, **Where**, **First day** and **Last day**. Verified live in the Planner in a headless browser.
- Anthropic refused every request made with an organisation-level key ("This API key is not scoped to a workspace, so this request must include the anthropic-workspace-id header"; found the moment the AI diagnostics landed). The host console's Anthropic row and an environment's AI configuration page (custom source) gain a **Workspace id** field, sent as `workspace` and carried as that header by the server half; a key made inside a workspace needs nothing there. The seed from the server's environment is `AI_ANTHROPIC_WORKSPACE`.
- The host console never got Font Awesome: `admin.<base>`'s own hostname resolver handed every request straight to `hostRouter`, whose catch-all 404'd `/fa/css/*` and `/fa/webfonts/*` before they ever reached the two static mounts that serve them (registered on `app`, since the bare base domain needs them too). Visible as the shared map files table's delete buttons drawing as empty red ovals -- any icon on the console was silently missing its font. Fixed the same way the bare base domain already exempts its own handful of paths: `/fa/` on `admin.<base>` now falls through past `hostRouter` to those mounts, Font Awesome Pro first if the admin has dropped one in, same as everywhere else.
- `server/region-cut.js`'s two "the world file address is not set up right" messages named a "Module Configuration" screen that does not exist anywhere in the product; reworded to "the world map address is not set" (`RegionCutJobs.estimate`/`start`, `validSource` false), leaving it to whichever page raised the error to say where to fix it -- on the console, the address field sits right above the region cutter itself.
- The same file's other two CLI-failure messages, in `reason()`, said "world file"; reworded to "world map" so every region-cut error shares the one noun -- "could not be reached" and, for a 404 or `NoSuchKey`, `answered "not found"; check the address` (that last clause replacing the same stale "Module Configuration" reference the `validSource` messages had).
